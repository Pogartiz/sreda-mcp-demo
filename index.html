Что оценивает SREDA-MCP

Может ли агент довести рабочую задачу до проверяемого результата

SREDA-MCP оценивает связку «модель × harness»: понимает ли агент постановку на русском языке и может ли шаг за шагом выполнить задачу через MCP в реальной рабочей среде — с настоящими файлами, приложениями и сервисами.

1 / 4 · Постановка

Одна задача связывает поиск, проверку изображений и подготовку документа

Агенту нужно собрать сведения обо всех партнёрах с веб-страницы, проверить технические параметры их логотипов и подготовить итоговый обзор для совета директоров.

  1. Загрузить страницу и собрать названия, описания и ссылки на логотипы.
  2. Проверить формат и ширину каждого логотипа.
  3. Для каждого партнёра вынести решение «годится / не годится» и указать причину.
  4. Собрать полный Word-документ со сводкой и сохранить его под заданным именем.
Задача пользователяdocs/task.md
Пользователь

Готовлю внутренний обзор партнёрств для совета директоров. На странице partnerships.html есть актуальная информация о наших партнёрах — названия, описания и ссылки на их логотипы. Собери информацию обо всех партнёрах, проверь каждый логотип: нужен PNG или JPG размером не меньше 200 px по ширине. Затем составь документ Word с заголовком «Обзор партнёрств — Q3 2025», датой, введением, разделом по каждому партнёру и сводкой. Файл назови Partnership_Review_Q3_2025.docx.

4 / 4 · Специализированная проверка

Оценка учитывает содержимое документа и способ его получения

Автопроверка открывает DOCX, ищет все разделы, проверяет решения по логотипам и итоговые числа. По сохранённой траектории она также видит, обращался ли агент к источнику, изображениям и Word.

PASS означает, что все шесть партнёров разобраны, решения подтверждены инструментами, а полный результат записан в документ.

Как устроен один прогон SREDA-MCP

Модель выбирает следующий вызов, harness исполняет его через MCP или локальный tool и возвращает ответ. После claim_done запускается проверка результата и траектории.

Решение следующий вызов или завершение
1 Модель

читает задачу, состояние рабочей среды и историю

2 Вызов tool

выбирает MCP или локальный tool и передаёт аргументы

3 Исполнение tool

harness выполняет действие в реальном сервисе или рабочей папке

4 Ответ tool

данные, ошибка и изменённое состояние возвращаются модели

выход из цикла claim_done

запускается проверка результата и траектории

Бенчмарку

Как определяется успех

После завершения проверка читает итоговую рабочую папку и сохранённую траекторию.

Эталонный результат groundtruth_workspace/

analysis_report.txt с корректными расчётами, курсами, прогнозом и ссылкой на диаграмму используется при разработке проверки.

Проверка результата evaluation/main.py
  • проверяет наличие и структуру analysis_report.txt;
  • сверяет курсы, план в рублях, проценты выполнения и средние значения;
  • ищет прогноз на II квартал и ссылку на созданную диаграмму;
  • по траектории подтверждает работу с источниками и файлами.
Итог прогона eval_res.json {"pass": true} или {"pass": false} с причиной ошибки

Как сравниваем модели и harness

Итоговая таблица собирает PASS/FAIL из проверки, статистику прогона и метрики вызовов tool относительно золотой траектории.

Набор метрик

Успешность

PassAtK(k=1) pass@1 ↑ Доля успешных отдельных запусков среди всех попыток.
PassAtK(k=3) pass@3 ↑ Доля задач, где успешна хотя бы одна из трёх попыток.
PassAllK(k=3) pass^3 ↑ Доля задач, где успешно завершились все три попытки.

Траектория и ресурсы

ModelCalls model calls ↓ Среднее число запросов к модели на одну задачу.
NumToolCalls tool calls ↓ Среднее число исполненных вызовов tools на одну задачу.
ToolSelectionAccuracy tool_acc ↑ Позиционное совпадение имён tools с золотой траекторией.
ToolRedundancy dupes ↓ Доля повторных вызовов одного tool с теми же аргументами.
TimeToSuccess time/task ↓ Среднее время выполнения задачи в секундах.
TokenUsage.total_tokens tokens/task ↓ Среднее число входных и выходных токенов на задачу.

Как формируются числа

pass@1успешные запуски / все запуски pass@3задачи с ≥ 1 успехом / все задачи pass^3задачи с 3 успехами / все задачи Вызовысредние model_calls и tool_calls из messages Время и токенысреднее значение на одну задачу Toolsсовпадение с эталонной траекторией; дубли считаются по name + args
